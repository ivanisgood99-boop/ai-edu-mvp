# 學生端登入與學習紀錄：瀏覽器端到端驗收計畫

> 更新日期：2026-11-24  
> 對應分支：`codex/learning-sync-level-access`  
> 對應 PR：[#3](https://github.com/ivanisgood99-boop/ai-edu-mvp/pull/3)  
> 狀態：測試案例已整理；尚未在瀏覽器執行。此分支尚未部署到正式 GitHub Pages。

## 1. 測試目的

這份清單用來驗證「瀏覽器 → Supabase Auth → 作答 RPC → 學習統計」的完整路徑。資料庫交易回滾測試與 JavaScript 語法檢查不能取代真實瀏覽器驗收。

## 2. 測試前置條件

1. 必須先有指向本開發分支的**預覽網址**。目前正式網址仍是 main 的版本，不可拿正式網站當作本分支已更新的證據。
2. 準備兩個專用測試學生帳號（學生 A、學生 B），不要使用真實學生資料。
3. 若 Supabase Auth 開啟電子郵件驗證，需先完成測試信箱驗證。
4. 測試時使用不同瀏覽器個人資料或無痕視窗，避免 A、B 的登入 Session 混在一起。
5. 測試帳號密碼、驗證信連結、Access Token、Refresh Token 都不要貼到聊天、Issue 或程式碼中。

## 3. 測試案例

| 編號 | 測試項目 | 操作 | 預期結果 |
|---|---|---|---|
| AUTH-01 | 新帳號註冊 | 用測試信箱註冊學生 A | 顯示註冊成功；若要求信箱驗證，未驗證前不應進入已登入狀態 |
| AUTH-02 | 首次登入 | 完成驗證後登入學生 A | 顯示資料庫 profiles 中的顯示名稱與學生首頁 |
| AUTH-03 | Session 持續 | 登入後重新整理頁面 | 仍是學生 A；不應短暫顯示錯誤的訪客資料 |
| AUTH-04 | 登出 | 點擊登出，再重新整理 | 回到登入畫面；不應繼續顯示 A 的個人資源 |
| AUTH-05 | 再次登入 | 使用 A 的帳號重新登入 | 可正確載入原本的資源與學習統計 |
| AUTH-06 | 帳號狀態 | 使用非 active 的測試帳號（若有）登入 | 不得進入學生功能；應顯示帳號未啟用訊息 |
| LEARN-01 | X-1 引導題 | 進入一個未完成 Level，提交引導題 | 作答同步成功；引導題只記錄 submitted，不把前端語意判定當成伺服器正確答案 |
| LEARN-02 | 理解檢查錯題 | 提交一題錯誤答案 | 伺服器紀錄為錯誤；不增加正確題數 |
| LEARN-03 | 理解檢查正確題 | 提交正確答案 | 伺服器紀錄為正確 |
| LEARN-04 | X-1 完成門檻 | 未完成所有 check 題前嘗試總結；之後補齊全部正確題再總結 | 前者不得完成 X-1；後者才可完成 X-1 |
| LEARN-05 | X-2 解鎖 | X-1 未完成時查看練習應用；完成 X-1 後再查看 | 未完成時鎖定；完成後可進入 X-2 |
| LEARN-06 | 練習與補救 | 在 X-2 完成一題正確 practice 或 remedial | 資料庫可保存紀錄並依伺服器答案鍵判定 |
| LEARN-07 | 重新載入還原 | 完成部分學習後重新整理、登出再登入 | X-1、X-2 與星級從伺服器資料還原 |
| LEARN-08 | 同步失敗 | 在測試環境模擬網路中斷後送出作答 | 不得誤報正式精熟度已更新；恢復連線後可重新同步 |
| ISO-01 | 學生隔離 | A 完成一題後登出，改登入 B | B 不得看到 A 的作答紀錄、星級或個人資源 |
| ISO-02 | 直接資料存取 | 以 B 的登入狀態嘗試讀取 A 的資料 | RLS 必須拒絕或回傳空結果；不得取得 A 的資料 |
| ISO-03 | 登出隔離 | A 登出後重新整理 | A 的舊資料不得留在登入畫面或 B 的工作階段 |
| TEACH-01 | 教師班級範圍 | 由已授權教師帳號讀取其班級學生資料 | 僅能讀取自己授權班級；未授權班級不可讀取 |

## 4. 每次測試的紀錄方式

每個案例只記錄以下資訊：

- 結果：通過 / 失敗 / 尚未測試
- 測試案例編號
- 發生時間（台灣時間）
- 錯誤訊息（移除信箱、姓名、Token 等個資後）
- 若有問題，記錄操作步驟與畫面上的非敏感訊息

不要提供帳號密碼、驗證連結、Token 或真實學生個資。

## 5. 測試完成後的資料清理

- 使用專用測試帳號與測試資料，不要用真實學生帳號測試。
- 測試結束後，由專案管理者依 Supabase Auth 與資料保留規則清理測試帳號及其測試資料。
- 不要直接刪除正式資料表或批次清空正式學生資料。

## 7. 本次程式碼檢查新增發現

- 前端原先忽略 profiles 與 student_resources 查詢錯誤，可能把讀取失敗偽裝成預設學生資料或零資源。本分支已改為：查詢錯誤、缺少必要資料或帳號狀態非 active 時明確失敗，不再使用 user_metadata 當作角色資料來源。
- 原先登出函式忽略 Supabase 回傳錯誤，現在會回報失敗，學生首頁也會顯示登出錯誤。
- 以上是程式碼修正，尚未以真實瀏覽器帳號驗證。
- Supabase Security Advisor 仍有其他既有 SECURITY DEFINER 函式與 RLS 無政策警示；目前沒有因為警示就任意撤銷功能權限。必須逐一確認呼叫者、函式內部的 auth.uid() 檢查與實際產品用途，再做最小權限修正。
